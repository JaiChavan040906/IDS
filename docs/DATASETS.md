# Datasets: what we used, where, and why

One main dataset builds and tests the AI, a few files are made from it, and one separate
dataset tests the AI on truly new traffic.

| Dataset | Where it lives | Used for | Did the AI learn from it? |
|---|---|---|---|
| **Improved CIC-IDS2017** | `data/raw/` (5 CSVs, 1.1 GB) | Training, tuning, testing, the website demo | Training part only |
| Train / validation / test / replay files | `data/processed/` (292 MB) | Cleaned, split versions of the dataset above | `train.parquet` only |
| GAN-generated samples | `artifacts/augment/synthetic.npz` | One experiment (augmentation) | That experiment only |
| **CSE-CIC-IDS2018** (2 days) | `data/external/` (655 MB, not in Git) | Testing on truly new data | Never |
| Small test samples | `.pytest_tmp/` | Automated software tests | Never |

## 1. Improved CIC-IDS2017 (main dataset)

- **What:** five days (Mon 3 to Fri 7 July 2017) of lab network traffic from the Canadian
  Institute for Cybersecurity, with attacks carried out on purpose and every flow labelled.
- **Version:** the improved release (Engelen et al., Liu et al.). It fixes the original
  release's labelling mistakes and re-measures traffic with an improved CICFlowMeter.
- **Source:** Kaggle `ernie55ernie/improved-cicids2017-and-csecicids2018`, folder `CICIDS2017`.
- **Size:** 2,099,976 flows, 91 columns, 27 labels. After cleaning
  (`scripts/prepare_data.py`): 1,714,812 flows, 13 classes, 64 measurements.
- **Why:** the reference paper used CIC-IDS2017 (comparable results); it is the most used
  flow-based IDS benchmark; the corrected version avoids errors that inflate scores.

## 2. How the main dataset was split

| Part | Flows | File | Used for | Why |
|---|---|---|---|---|
| Training 70% | 1,200,368 | `train.parquet` | Training every model; fitting the data-cleaning settings; the 200,000-row memory sample in retraining | The AI studies these |
| Validation 15% | 257,222 | `val.parquet` | Choosing settings, calibration, routing thresholds, fixed benchmark for retraining's acceptance rules | Tune without touching the final exam |
| Test 15% | 257,222 | `test.parquet` | Final scores, run once (`reports/final/`) | The locked final exam |
| Replay file | 257,222 | `replay.parquet` | The website's traffic simulation: test flows in time order with IPs added back for analyst context | The demo only shows traffic the AI never trained on |

Leave-one-attack-out and the day split (`scripts/generalisation.py`) used training and
validation rows only, never the test split.

## 3. GAN-generated samples

About 12,900 artificial flows for six rare attack types, generated by a cWGAN-GP trained on
the training split only (`scripts/train_augmenter.py`). Used only in the "CNN-LSTM +
augmentation" experiment. The gain was smaller than seed-to-seed variation and the samples
were easy to tell from real ones, so the deployed model does not use them.

## 4. CSE-CIC-IDS2018 (truly new data)

- **What:** traffic recorded in 2018 on a different, larger network by the same institute.
- **Source:** the institute's public archive (`cse-cic-ids2018` on Amazon S3, no login).
- **Files tested** (random sample of 499,854 flows from each 1,048,575-row file):

| File | Tested sample |
|---|---|
| Friday-16-02-2018 | Normal 212,601, DoS Hulk 220,894, DoS Slowhttptest 66,359 |
| Friday-02-03-2018 | Normal 363,433, Botnet 136,421 |

- **Used for:** scoring the frozen v1 model with `scripts/evaluate_csv.py`. No training, no
  tuning; labels only used to score afterwards. Reports: `reports/external/`.
- **Result:** on its own the CNN-LSTM caught 0.16% of the botnet traffic. The routing
  flagged the data as unfamiliar and sent 98-100% to review, so no attack was missed, but
  analysts would have to check almost everything.
- **Caveat:** this is the original 2018 release, measured with the older CICFlowMeter, so
  part of the failure is the measurement tool and not only the new network.

## 5. Small test samples

CSVs of 300-400 flows built from the replay file, some with columns renamed to mimic the 2018
naming or with labels removed. They check the software (website, importer, upload) and say
nothing about the model's accuracy.

## Not used

| Dataset | Why not |
|---|---|
| Original (uncorrected) CIC-IDS2017 | Known labelling errors and measurement bugs |
| CIC-IoT2023 | Different measurements (IoT); future scope |
| KDD Cup 99, NSL-KDD, UNSW-NB15 | Different features from different tools |
| Improved CSE-CIC-IDS2018 | **Recommended next**: 2018 traffic re-measured with the same improved tool as our training data, to separate "new network" from "old tool". Kaggle, folder `CSECICIDS2018` (needs a Kaggle login) |

## The rule

Learn from training only, tune on validation only, test once on test, and judge real-world
ability on a different dataset.
